03 · The skills

Four skills for the flow

  1. /jira-plan

    Interrogates me, then writes one plan for every repo

  2. /jira-review

    After implementing: is it what the plan says?

  3. /code-review

    Then: is the code right?

  4. /jira-ship

    Commits and opens the pull requests

The plan they share: .working-docs/VFS-1234.md

Separate, not part of the flow

/jira-refine posts questions on a story before refinement

04 · The workflow

Story to PR

  1. Scope work

  2. Plan from the story /jira-plan

  3. Review the plan

  4. Implement

  5. Manual testing

  6. Review /jira-review /code-review

  7. Ship /jira-ship

05 · The story

Plan from the story

  • The Jira ID, once
  • Nothing copied by hand
  • One plan for every repo
/jira-plan

knows   VFS-1234 from the feature
reads   the story, its comments
        and acceptance criteria
reads   the code in every repo
asks    what it cannot decide
writes  .working-docs/VFS-1234.md
06 · Test and review

Test, review, then ship

  • ▶

    Does it work?

    Manual testing, when the change needs it.

  • ≡

    Is it what we agreed?

    /jira-review, against the plan.

  • ⌕

    Is the code right?

    /code-review, against main.

  • ↗

    Ship it

    /jira-ship: a commit per phase, pull requests in order.
