01 · The workflow

Story to PR

  1. Feature folder wag cpyolo

  2. Plan from the story /jira-plan

  3. Review the plan

  4. Implement

  5. Manual testing

  6. Review /jira-review /code-review

  7. Ship /jira-ship

02 · The agents

Sol decides, Luna helps

Sol · the orchestrator
  • Runs the skills and implements
  • Decides what to hand to Luna
  • Supervises Luna, checks everything
Luna · the worker
  • One task, in one repo
  • Searches, writes code, runs tests
  • Reports back to Sol
03 · The skills

Four skills for the flow

  1. /jira-plan

    Interrogates me, then writes one plan for every repo

  2. /jira-review

    After implementing: is it what the plan says?

  3. /code-review

    Then: is the code right?

  4. /jira-ship

    Commits and opens the pull requests

The plan they share: .working-docs/VFS-1234.md

Separate, not part of the flow

/jira-refine posts questions on a story before refinement

05 · twg

Jira, through twg

twg jira workitem get VFS-1234
  • Reads the story and its comments
  • Deferred questions go back in one comment
  • Posted only when I confirm
06 · Test and review

Test, review, then ship

  • ▶

    Does it work?

    Manual testing, when the change needs it.

  • ≡

    Is it what we agreed?

    /jira-review, against the plan.

  • ⌕

    Is the code right?

    /code-review, against main.

  • ↗

    Ship it

    /jira-ship: a commit per phase, pull requests in order.
